## 2. 为什么编码器损坏时原程序不能继续运行

原来的电机控制是速度 PI：根据“目标编码器计数 − 实际编码器计数”计算输出。编码器断开后，即使电机在转，反馈也可能一直为零，于是速度误差一直为正，积分继续增加，PWM 逐步变大。

另外，原程序对反向计数、过大计数进行故障检查，并在 PWM 达到一定值、计数长期接近零时判为堵转。编码器损坏会触发这些条件。仅取消故障停车无法解决 PI 积分持续增大的问题。

原圆环流程还要求 IMU 数据有效，用累计转角判断绕行一圈和出环。这也不符合“仅依靠视觉”的目标。

## 3. 修改思路

### 3.1 保留已经基于图像工作的转向闭环

图像处理仍采用现有白色宽路面识别：灰度分割、边缘搜索、近中远中线融合，输出归一化偏差 `err_norm`、弯曲指标 `bend_norm`、置信度及有效性。

转向仍调用 `car_pid_steering_step()`：

```text
e = clamp(err_norm / 1000, -1, 1)
微分项 = 对相邻有效图像帧的误差变化率进行低通滤波
舵机目标 = 中位 + 方向符号 × (Kp × e + Kd × 微分项)
```

沿用舵机脉宽限位 1340～1740 μs、中位 1540 μs，以及每 10 ms 最大变化 12 μs。首帧和丢线恢复时清除微分历史，重复时间戳不会重复更新转向。以上机械参数仍需在实车上校准。

### 3.2 用视觉决定驱动力，不再计算编码器速度 PI

原 `car_turn_plan()` 的路径规划公式继续复用；纯视觉模式下，其输出单位切换为 PWM 数值：

```text
severity = clamp(1.3 × abs(e) + bend_norm / 650, 0, 1)
平均 PWM 目标 = 1100 − (1100 − 800) × severity
置信度低于 65，或远处有效行少于 3：目标最多 650
```

PWM 满量程为 10000，因此上述数值对应 11%、8%、6.5% 占空比。它们不是米/秒、转/分钟，也不是测得的车速。视觉仅提供路径和道路状态反馈，本次没有实现光流测速或视觉里程计。

根据已经限幅、渐变的舵机指令，继续分配左右轮目标：右转时左轮目标较大，左转时右轮目标较大；最大分配比例为 15%。这里没有舵角传感器反馈，使用的是发送给舵机的指令脉宽。

左右轮分别应用补偿系数，最后分别执行 PWM 变化率限制与硬限幅。默认单轮最大输出为 1500，即 15%；每个 10 ms 周期最多增加 10、正常减小最多 40。由于最终限制位于差速和补偿之后，这两项不会绕过输出上限。

程序不会因为“没有编码器计数”持续增加输出，也不会自动施加额外起步冲击。

### 3.3 从硬件入口取消传感器依赖

- 纯视觉模式不调用编码器初始化、读取、清零函数，因此损坏编码器的输入不参与控制。
- 纯视觉模式不初始化、采样 IMU，`car_control_motion()` 直接忽略输入。
- 停用依赖 IMU 的圆环状态机；纯视觉模式强行启用该状态机会产生编译错误，避免混用。
- 屏幕启动提示改为 `VISION / OPEN PWM`，串口报告 `speed:NA` 和 `duty_target`，避免把未测量的速度显示成有效反馈。

### 3.4 保留基于视觉和按键的停车逻辑

| 情况 | 行为 |
|---|---|
| 上电或初始化 | 电机 PWM 为零，不自动启动 |
| 连续 3 帧有效且无岔路歧义，并按键3 | 允许启动；等待下一帧有效图像后逐步给出驱动力 |
| 单帧无效或无法处理的岔路 | 目标置零，下一次控制调度切断 PWM；保持此前舵机目标 |
| 连续 3 帧丢线 | 锁存图像故障停车 |
| 连续 3 帧岔路歧义 | 锁存岔路故障停车 |
| 超过 150 ms 无新图像 | 控制调度锁存图像故障并切断 PWM |
| 按键4 | 10 ms 控制中断直接检测并停车，不依赖主循环刷屏完成 |
| 故障后图像恢复 | 不自动启动；重新满足有效图像条件后需要按键3 |
| 临时丢线后恢复且未达到锁存门槛 | 从零重新建立 PWM 目标，不沿用丢线前的高目标 |

由于没有可信轮速反馈，纯视觉模式停用编码器异常和基于编码器的堵转检测。这不代表堵转问题得到检测或解决。PWM 归零表示撤销驱动力，当前接口下通常是滑行，并不等于机械立即停止。

## 5. 默认配置及调试顺序

| 参数 | 当前值 | 用途 |
|---|---:|---|
| `CAR_DRIVE_ENABLE` | 1 | 初始化驱动输出，上电仍停车；设 0 可仅做图像预览 |
| `CAR_VISION_ONLY` | 1 | 纯视觉模式；设 0 恢复传统编码器 PI / IMU 圆环方案 |
| `CAR_OPEN_PWM_STRAIGHT` | 1100 | 平直清晰路面的平均 PWM 目标 |
| `CAR_OPEN_PWM_BEND` | 800 | 大偏差或明显弯曲时的平均目标 |
| `CAR_OPEN_PWM_CAUTIOUS` | 650 | 低置信度/远处信息不足时的平均目标上限 |
| `CAR_OPEN_PWM_LIMIT` | 1500 | 每个电机最终 PWM 上限 |
| `CAR_OPEN_PWM_ACCEL / DECEL` | 10 / 40 | 单轮每 10 ms 的正常变化限制 |
| `CAR_OPEN_PWM_TRIM_L / R` | 1.0 / 1.0 | 两侧电机输出补偿，最终仍受限幅约束 |
| `CAR_STEER_KP / KD` | 150 / 6 | 原有视觉转向 PD 初始参数 |
| `CAR_TURN_SPEED_RATIO` | 0.15 | 左右轮目标的最大差速比例 |

建议先确认摄像头能够稳定提取白色路面，再架空确认电机正转、舵机中位和限位。图像道路偏右时，车轮应向右转；不一致时校准 `CAR_SERVO_SIGN`。左右电机前进方向继续由原 `CAR_MOTOR_*_FORWARD` 配置。

低速落地调试时先观察是否能够起步、是否沿中线行驶。PWM 参数会受电池电压、轮胎摩擦和电机差异影响，需要实测调整；没有测得车速时不能把增加 PWM 解释为准确提速。若左右电机存在稳定差异，可小幅调整补偿系数；若只有单驱动电机和机械差速器，应将软件差速比例设为 0 并核对硬件接口。

普通弯道的连续视觉跟随仍然支持。对圆环岔口，本次没有新增纯视觉绕一圈计数、出口识别、直角弯或掉头算法。遇到无法明确选择道路的岔口会停车，不能声称具备完整纯视觉圆环通过能力。
