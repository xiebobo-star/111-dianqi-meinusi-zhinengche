# TC264 多级菜单 + 参数掉电保存（工程名：menu）

> 本工程已将菜单应用层合并到 `TC264_Servo_BDS300`。当前菜单第一组参数用于 BDS300 舵机：脉宽us（命令值，唯一真值）、角度（0.1° 精度，由脉宽换算，可反过来改）、Pulse min、Pulse center、Pulse max、Pulse enable；舵机信号输出为 P33_9（ATOM1 CH1 / TOUT31；原 P21_6）。脉宽与角度双向联动，编辑时短按一档、长按 10 档连发。下文中原菜单工程的“电机参数”描述在当前项目中对应 Servo 参数组。

> AURIX Development Studio 1.10.40 / 逐飞 TC264 开源库 / 主控板 TC264主控板V1.2
> 工程路径：`D:\Infineon\AURIX-v1.10.40-workspace\menu`

## 一、这个工程做了什么

| 作业要求 | 本工程实现 |
|---|---|
| 1. 任意多级菜单（≥2 级） | 四级深度：主菜单 → 子菜单 → 参数组页面 → 修改态；菜单树用数组描述，加菜单只加一行 |
| 主菜单 3 项：参数设置 / 状态查看 / 系统信息 | 完全一致（主菜单 3 项，每项下面 3~5 个子菜单） |
| 每个主菜单下 2~3 个子菜单 | 参数设置：电机参数 / 传感器参数 / 系统参数（+ 保存全部 / 恢复全部默认）<br>状态查看：运行状态 / 存储状态 / 参数总览<br>系统信息：版本信息 / 硬件信息 / 操作说明 / 按键自检 |
| 文字清晰无毛刺 | 16×16 宋体点阵（`tools/gen_font.py` 自动生成，当前 146 个汉字），另配库自带 8×16 ASCII 字库 |
| 切换时有明显视觉反馈 | 选中项 = 填色高亮条 + 左侧 `>` 箭头；子菜单右侧另有 `>`；正在修改的项 = 黄色高亮 + 两侧尖角箭头 |
| 逐飞 LCD 驱动画菜单框架 | `menu_display.c` 只用 `ips200_*` / `tft180_*` 库函数（含自己用画线拼的填充矩形） |
| 按键扫描 + 消抖 | **工程自己写的扫描**（`user/menu_key.c`）：20ms 消抖 + 事件锁存 + 长按 + 按住连发，10ms 定时中断里扫（不用库 `zf_device_key`，原因见「三、按键操作」） |
| 2. 用片内 Flash 存数据 | TC264 内置 DFlash 96KB=12 页，用第 10/11 页，**不需要外部存储芯片** |
| 至少 3 组常用参数、每组任意个数据项 | 3 组、共 12 项（电机参数 5 项 / 传感器参数 3 项 / 系统参数 4 项），加参数只改 `menu_param.c` 两张表 |
| 按键修改 + 控制保存 | 参数页按确定进入修改，按键 1 加 / 按键 2 减 / 确定 写入；保存要选「保存本组参数」或「保存全部参数」 |
| 保存时弹窗确认，防误操作 | 居中弹窗「确认保存本组参数?」，确定才写 Flash，取消就什么都没发生 |
| 菜单里显示存储状态 | 参数页标题右上角：`已保存` / `未保存`；另有「状态查看 → 存储状态」页显示 A/B 页是否有效、保存序号、参数来源、上次保存结果、保存次数、未保存组数 |
| 断电重上电自动读回 | 上电 `menu_param_init()`（填默认值）→ `menu_flash_load()`（Flash 里有有效数据就覆盖），开机提示「已载入上次参数」 |

额外做的：核心板 LED 保存成功闪一下（可用菜单里的「LED指示」参数关掉）、串口同步打印 ASCII 日志（屏幕没调通也能确认逻辑跑没跑）、双页备份 + 写后回读校验（保存过程中断电不会把参数全丢）、**按键自检页**（按哪个键哪行变「按住」，一眼看出线有没有问题）。

## 二、接线（主板 → TC264）

| 功能 | 主板丝印 | TC264 引脚 |
|---|---|---|
| 屏幕 SPI2 | SCK / MOSI / CS / RST / DC / BLK | `P15_3` / `P15_5` / `P15_2` / `P15_1` / `P15_0` / `P15_4` |
| 按键 1 | 按键1 | `P20_6`（上选） |
| 按键 2 | 按键2 | `P20_7`（下选） |
| 按键 3 | 按键3 | `P11_2`（确定） |
| 按键 4 | 按键4 | `P11_3`（返回；长按 = 回主菜单） |
| 核心板 LED1 / LED2 | — | `P20_9` / `P20_8` |
| 调试串口 | TX / RX | `P14_0` / `P14_1`（115200） |

注意事项：
1. 屏幕 **VCC 必须接 3.3V**（主板屏幕座就是 `VCC3V3`），接 5V 必黑。
2. 屏模块脚序和主板丝印不是一套名字，**一根根按名字对**：屏 `SCL→SCK`、`SDA→MOSI`、`BLK→BLK`。
3. 现在用的是 1.8 寸 TFT180（128×160）；杜邦线接屏若花屏，把 `libraries/zf_device/zf_device_tft180.h` 的 `TFT180_SPI_SPEED` 从 60MHz 降到 30MHz 再试 15MHz。
4. 换屏只改一个开关：`menu_config.h` 的 `MENU_DISPLAY_USE_IPS200`（**0 = 1.8 寸 TFT180 128×160，现在是这个**；1 = 2 寸 IPS200 240×320）。行高、首行 y、一屏行数会跟着自动换（TFT180 一屏 6 行，超了会滚动）。
5. P21_4 / P21_5 被电机信号接口占了，别当 LED 用。

## 三、按键操作

| 场景 | 按键 1 | 按键 2 | 按键 3 | 按键 4 |
|---|---|---|---|---|
| 菜单列表 | 上选（按住连发） | 下选（按住连发） | 进入 | 返回上一层（已在主菜单时提示「已在主菜单」） |
| 参数组页面 | 上移 | 下移 | 进入修改 / 执行「保存本组参数」 | 返回上一层 |
| 正在修改某个参数 | 加一档（按住连发） | 减一档（按住连发） | 确认（值写入菜单，标「未保存」） | 取消本次修改 |
| 弹窗确认 | — | — | 确定 | 取消 |
| 信息 / 状态页 | — | — | 退出 | 退出 |
| 按键自检页 | 检测用 | 检测用 | 检测用 | 检测用（按它退出自检页） |
| **任意页面：长按按键 4** | — | — | — | **直接回主菜单** |

- 4 个键各管一件事：**1 上选、2 下选、3 确定、4 返回**。
- 上下选**按住 0.45 秒后自动连发**（每 90ms 一格），翻长列表不用一下一下点。
- 在更深层页面时，长按按键 4 可以一步跳回主菜单。

### 按键为什么不直接用库里的 `zf_device_key`

库里的 `key_scanner()` 有两个坑，**「确定」这种一点就松的动作最容易中招**（症状就是「按了没反应」，上选下选因为你会连按或按住反而看着正常）：

1. `key_press_time` 记的是**扫描次数**，却直接跟 `KEY_MAX_SHOCK_PERIOD`（10，本来是 ms）比 —— 扫描周期 10ms 时必须**按住 100ms 以上**才算一次短按，快点一下会被当抖动丢掉。
2. 短按标志只在**松手那一次扫描**里存在，下一次扫描（10ms 后）就被清成 `KEY_RELEASE`。主循环正在刷屏（整屏 20~60ms）时就彻底错过了。

所以 `user/menu_key.c` 自己写了扫描：

- 电平连续 2 次（20ms）一致就认，消抖还是 20ms
- **松手一定产生一个「短按」事件**，而且事件**锁存**到被主循环读走为止（主循环再慢也不会丢）
- 长按（800ms）、按住连发（450ms 起、90ms 一格）都按周期算准
- 引脚、消抖次数、长按时长、连发速度全在 `menu_config.h` 里：`MENU_KEY_PIN_UP / DOWN / OK / BACK`，换键只改这 4 行

### 按了键没反应时先看「按键自检」页

`系统信息 → 按键自检`：

```
按键1 P20_6 上选 松开
按键2 P20_7 下选 松开
按键3 P11_2 确定 按住     ← 你按哪个键，哪一行就变成「按住」
按键4 P11_3 返回 松开
次数 3 5 7 2            ← 每个键累计按了几次
```

- 按下去某行变「按住」、松开变回来、次数 +1 → 这个键和这根线都是好的
- **某个键怎么按次数都是 0** → 这个键本身 / 那根线有问题（没焊好、按键坏、丝印对错）。修好后不用改代码，它就是第二个确定键；也可以把 `menu_config.h` 里对应那个 `MENU_KEY_PIN_xxx` 改成别的脚
- 自检页里短按按键 1/2/3 都不会跳走，**按按键 4 退出**
- 串口（115200）也会按物理键分开打日志：`[key] 3 P11_2 ok`、`[key] 4 P11_3 back`、`[key] long 4 = home`，屏上现象对不上时看串口最直接

## 四、跑一遍的流程（答辩演示顺序建议）

1. 上电，屏幕显示主菜单，标题右边是 `1/3`，底部是高亮条 + 提示行。
2. `参数设置 → 电机参数`：能看到 5 个参数 + 末尾「保存本组参数 / 恢复本组默认」，标题右边显示 **已保存**。
3. 选中「目标速度」按确定 → 整行变黄、两侧出现箭头 → 按键 1/2 加减 → 确定 → 标题右边变成 **未保存**。
4. 选「保存本组参数」按确定 → 弹窗「确认保存本组参数?」→ 确定 → 提示 **保存成功**，LED 闪一下，标题变回 **已保存**。
5. `状态查看 → 存储状态`：能看到 `页A: 有效 序号1 / 页B: 空 序号0`、`参数来源: Flash`、`上次保存: 成功`、`保存次数: 1`。
6. **拔电再上电** → 开机提示「已载入上次参数」 → 进「电机参数」看，刚才改的值还在（这就是掉电保存）。
7. 再保存一次 → 这次写的是 **页B**（A/B 轮流），存储状态页里能看到序号变大、两页都有效。
8. 选「恢复本组默认」→ 弹窗确认 → 值回到默认，标题变 **未保存**，再保存才写进 Flash。
9. `系统信息 → 按键自检`：4 个键各按一下，看哪行变「按住」。

## 五、工程结构（自建文件全在 `user/`，库文件一行没改）

| 文件 | 作用 |
|---|---|
| `user/menu_config.h` | **唯一配置文件**：屏幕型号、4 个按键引脚、消抖/长按/连发参数、Flash 页号、界面排版、颜色、版本号、参数表下标 |
| `user/menu_display.c/.h` | 屏幕封装：IPS200 / TFT180 用宏切；中英混排显示、填充矩形、边框、文本宽度 |
| `user/menu_font.c/.h` | 16×16 汉字点阵表（自动生成，别手改）+ 查表函数 |
| `user/menu_key.c/.h` | 按键扫描（20ms 消抖 / 短按锁存 / 长按 / 按住连发）+ 每键累计次数 + 引脚名（自检页用） |
| `user/menu_param.c/.h` | 参数表（3 组 12 项：名字 / 类型 / 默认值 / 上下限 / 步进 / 小数位 / 单位）+ 运行时值 + 未保存标志 |
| `user/menu_flash.c/.h` | 片内 DFlash 读写：双页备份、魔数 + 校验和、写后回读校验、状态查询 |
| `user/menu_ui.c/.h` | 菜单状态机：菜单树、参数页、修改态、弹窗、提示框、信息页、参数总览页、按键自检页 |
| `user/cpu0_main.c` | CPU0 主程序：初始化 → 菜单主循环 |
| `user/cpu1_main.c` | CPU1 只做基本初始化（菜单全在 CPU0，屏幕不要在两个核里重复初始化） |
| `user/isr.c` | 10ms 定时中断：按键扫描 + 界面计时（只放轻活，写 Flash 在主线程序里） |
| `tools/gen_font.py` | 汉字点阵生成脚本（扫源码字符串 → 生成 `menu_font.c`） |

## 六、Flash 存储格式

用片内 DFlash 第 10 页（A）和第 11 页（B），一页 4KB = 1024 个 `uint32`，参数只占前 20 个：

```
[0] 魔数 'ZFPM'    [1] 版本号 V1.0   [2] 保存序号（每保存一次 +1）
[3] 参数项数       [4] 参数组数      [5] 保留
[6] 校验和（前 20 个字求和，防掉电写坏）   [7] 保留
[8] 起：12 个参数值（int32，顺序和 menu_param_value[] 一致）
```

- 保存流程：**擦页 → 写 20 个字 → 回读比对**（对不上就报「保存失败」，参数不会被弄坏）
- 双页策略：A/B 都有效时写**序号小的那页**（旧页），只有一页有效就写另一页 → 任何时刻至少有一页是完整的
- 载入流程：两页都校验 → 取**序号大的**那页 → 逐项限幅后载入（坏数据不会越界）
- 擦写寿命约 10 万次：只在按「保存」时写一次，绝不在循环 / 中断里写

## 七、怎么加 / 改参数（改完重新跑一次字库脚本）

1. 在 `user/menu_param.c` 的 `menu_param_item_table[]` 加一行：
   `{"转向Ks", MENU_VAL_FIXED, 2, 100, 0, 2000, 5, NULL},  // 名字,类型,小数位,默认,最小,最大,步进,单位`
2. 在 `menu_param_group_table[]` 里把对应组的 `item_num` 加 1（`first_item` 跟着往后挪）。
3. 如参数项总数变了：把 `MENU_PARAM_ITEM_MAX` 和 `menu_config.h` 里的 `MENU_PARAM_IDX_*` 下标同步一下。
4. 新写了中文文案 → 在工程根目录跑 `python tools/gen_font.py` 重新生成字库（不跑的话新字在屏上是空白）。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 屏全黑 | 先量屏 `VCC–GND` 是 3.3V 还是 5V；屏幕座必须是 `VCC3V3`。只插下载器 = 没供电（5V 轨只有 3.1V） |
| 背光亮但花屏 | SPI 太快（杜邦线），把 `zf_device_tft180.h` 里的 `TFT180_SPI_SPEED` 降到 30MHz / 15MHz |
| 显示的是英文乱码 / 汉字空白 | 屏幕型号开关选错（IPS200 设 1、TFT180 设 0），或字库没重新生成 |
| 按键不灵 | 先看「系统信息 → 按键自检」：某键次数一直是 0 = 那个键/那根线的问题（改 `MENU_KEY_PIN_xxx` 或修线）；四个键都没反应 = 10ms 中断没跑（`pit_ms_init` 没调用 / 优先级冲突），或 `MENU_KEY_SCAN_PERIOD_MS` 和中断周期不一致 |
| 某个键按了没反应 | 先看「系统信息 → 按键自检」：那个键那行不变「按住」、次数不涨，就是键/线的问题；`menu_config.h` 里 `MENU_KEY_PIN_UP/DOWN/OK/BACK` 对应 4 个脚 |
| 保存报「保存失败」 | Flash 那一页被别的程序占了（`menu_config.h` 里换页号，默认用 10/11） |
| 保存成功但断电后没读回 | 上电时 `menu_flash_load()` 必须在 `menu_param_init()` 之后调用（见 `menu_ui_init()`） |
| 调试报「A debugging session is already running」 | 上一次调试会话没 Terminate（ADS 同时只允许一个会话） |
